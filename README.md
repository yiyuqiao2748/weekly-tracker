## 这份板子能做什么

### 周与看板

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 按周查看 | `◀` `▶` / 周标签 | 周键格式 `YYYY-Www`（ISO 周）。**打开页面永远落在真实当前周**，不记住上次浏览的周 |
| 回到本周 | 工具栏「回到本周」 | 从历史周一键回来 |
| 四条人列 | 看板 | `C.MEMBERS` 决定列顺序，每列一位成员 |
| 拖拽排序 | 按住卡片拖动 | Pointer Events 实现；**拖到别的列就是改派负责人**，不只是换位置 |
| 列头负荷条 | 列头右侧、完成数下方 | 最近 8 周每人任务数的迷你格（sparkline），当周那格高亮，空白周刻意压到几乎看不见 |
| 搜索 | 工具栏输入框 | 匹配任务名与备注，实时过滤 |
| 状态筛选 | 全部 / 未开始 / 进行中 / 已完成 | 与搜索叠加生效 |
| 完成度统计 | 顶部图签式统计条 | 总数、进行中、已完成、完成率（≥80% 好 / ≥50% 警告 / 其余标红） |

### 任务卡与编辑

| 字段 | 取值 | 备注 |
| --- | --- | --- |
| 名称 | 自由文本 | |
| 优先级 | 高 / 中 / 低 → 图纸代号 P1 / P2 / P3 | 标注式：代号 + 下画线，红/琥珀/绿三色 |
| 状态 | 未开始 / 进行中 / 已完成 | 与进度**互相联动**，见下 |
| 进度 | 0–100% | 以**尺寸线**呈现：**按住即拖**，无需先点击激活 |
| 开始 / 截止日期 | 日期 | 空白时读作 `·····` 占位 |
| 备注 | 自由文本 | |
| 顺序 | `order` | 拖拽写入，决定列内排列 |

所有字段**就地内联编辑**（点文字直接改，`Enter` 提交、`Esc` 取消），不弹窗、不跳页。

进度与状态双向联动，改完值还是原值的话不留修订痕、也不占撤销栈的一格：

| 动作 | 结果 |
| --- | --- |
| 进度拖到 100% | 状态自动置「已完成」；拖到 0 自动回到「未开始」；中间值置「进行中」 |
| 状态选「已完成」 | 进度顶到 100%；选「未开始」归 0 |
| 状态选「进行中」 | 进度被夹进 1–99（0 → 1，≥100 → 99），不允许「进行中=没开始」或「进行中=已做完」 |

### 修订记录与跨周对比

- 每个字段每次改动都留一条 `history`（`{at, field, from, to}`，每张卡最多保留最近 30 条），点卡片上的 **`REV n`** 徽标展开该卡的**修订表**——图纸上「改了几版」就是这一栏。状态与进度互相联动时，被带着改的那一项也会单独留一行，否则修订表会缺一条。
- 卡片右上按**本周相对上周**的状态打标：`新增`（上周没有这条任务，卡片外框画成内侧虚线，读作修订云线的轻量版）、`REV n`（跨周改过）。跨周算不算「修订」只看任务定义字段（优先级 / 起止日期 / 备注），**改进度和状态不算改版**。
- **第三枚 `第 N 周`**：这条任务在**同一个人名下连续在册**到第几周（含本周），看板和纸上印的是同一个数。那两枚都是**反着说**的（「上周没有」/「上周改过」），一条排到第五周的活与一条刚排第二周的活在纸上原本长得一模一样，而读一叠纸的人第一句问的恰恰是「这项压在他身上第几周了」。只在 `> 1` 且状态不是「已完成」时印——「第 1 周」与「新增」是同一句话，虚线框已经说了它，不必占一格；`≥ 4` 时整枚反白（锈红底），一叠纸扫过去先看到重的。判据与前两枚出自**同一次遍历**，所以「上一周没有」与「第 1 周」永远不会各说各话。
- **同一枚徽标的第二种说法：`断后第 N 周`**。中间断过一周以上的，重开之后数到的那一周起，前面多「断后」两个字（断口之前还有几周在册才算断过，所以「第 1 周」永远不会带前缀）。**不添新元素、不添新颜色、不改字号** —— 纸上「第 2 周」与「断后第 2 周」从此不是一句话。文案是九个候选一起量过版面代价选的（折行 0、行内溢出增量 0，最贵那个加宽 56px 也没弄坏纸），代价记在 `PROGRESS.md` 决策 23。
- 这枚徽标的版面代价量过再花：卡片那一行**槽里只要有任意一枚徽标就是 15px、全空才是 13px**，所以每张带标的卡 **+2px**（`REV` 已经在同一槽里的卡**零成本**）。全部留档里只有两格读数因此动了：纸面那册的自然高 **1450 → 1455**（配平 `0.7213 → 0.7189`），移动端长图整页高 **2696 → 2703**。同时目录页脚添一句人话：`未完成里 N 项已连续在册到第 2 周以上，最长的一项在纸上印着「〔断后〕第 M 周」；其中 K 项印的是「断后第 N 周」……`——一册十几张纸时，这句比逐张找徽标管用。**引号里那串字必须与纸上真印的一致**：`K` 与前缀出自同一个判据（`earlier > 0`），而「最长的一项」只有在并列最长的那几枚**全**断过时才带「断后」两个字。**（那一格里 `1450 → 1455` / `0.7213 → 0.7189` 是第八轮的读数；第九轮把缩放改判成「只压图面」之后，`fit-strip` 那格 `--fc` 读 **0.6639**、自然高 1455 未动 —— 见 `PROGRESS.md` 决策 22 与「还欠着的」里那条就地追记。**第十二轮起「1455 未动」这句到此为止**：预算的除数换成 `COMFORT_FLOOR`(.8824) 之后那张 1455px 的纸装不下 21 项了，这一例摊成两张，`fit-strip` 现读 `natH [1145, 1047]` / `--fc [0.8907, 1.0000]` / 摘要「2 张 · … · 续排 1 张 → 2 张 · 图面配平 89%」，见决策 25 与「版面留档」第 15 条。）**
- 撤销一次「新增」= 从板上拿掉它**并给它立墓碑**，否则下次合并它又从云端回来。

### 周与周之间

- **复制上周未完成**（工具栏）：把上一周状态非「已完成」的任务整片带进本周，保留进度与备注；这一步可整片撤销（`uncopy`）。
- 跨周比对用 `weekKey = person + ␟ + name`：同一负责人 + 同名任务算同一条，`新增`、跨周 `REV` 与 `第 N 周` 都是这么判出来的。**这个键不能换成卡片 `id`**——同一项活每周复制过来都是新 `id`（云端那 69 条任务有 69 个 `id`，却只落在 28 个身份上，其中 15 个身份出现不止一次，最忙的一条占了 9 周、9 个不同的 `id`），拿 `id` 判跨周就等于什么都判不出来。`第 N 周` 数的是这个键在**相邻**周里连着出现过几次，中间断一周就从头数起；**断过再重开的那一条，纸上前面会多「断后」两个字**（判的就是这一段起点之前还有几周在册，见上一条）；周先经 `weekOrdinal()` 化成整数（写法对、但那一周压根不存在时判 `null`，不参与数数——真碰上畸形周，那张卡两枚徽标都不印），再只往回看，不看未来。

### 出图（晒图）

工具栏「晒图」打开**晒图设置**，五个旋钮决定这一册图怎么排：

| 旋钮 | 取值 | 说明 |
| --- | --- | --- |
| 截止周 | 有数据的周 + 本周往前 7 周 | 连排是**从这一周往回数**，所以默认值就是本周；空周也能选，连排时它是「本周没排」的证据 |
| 连排周数 | 1–8 周 | 1 周＝单张。上限取「8 周」与「16 张纸」中先到那个：按人成册时 8 周会被压到 3 周，摘要当场说明。**那个 16 数的是真会印出来的纸**——续排把一张切成两张之后也会回头复核（见下面那条） |
| 分册方式 | 按周连排 / 按人成册 | 按周：一周一张 A3，四条人列＝四个 `分图 01…04`；按人：一人一卷 `VOL 01…04`，**卷内按周从旧到新**，每张纸的页眉还写「本卷 k / m」（见下），那人那周没活就不出空页 |
| 收录范围 | 全部任务 / 只出未完成 / 沿用当前筛选 | 只影响纸面；列头的负荷迷你格不受范围影响，它读作这个人的历史节律 |
| 首页加图纸目录 | 勾选，且多于一张时生效 | 加一张**图纸目录**页：张次 / 图号 / 图名 / 周期 / 册 / 任务 / 完成 / 率；按人成册时每卷开头是一条**卷小计**组头行（见下）；同一张目录页下面另起一张**任务分布横表**（人 × 周，见下） |

- 纸张 **A3 横排**、边距 10mm，可印区 400×277mm。每张纸固定按 **1512×1047 CSS px**（96dpi 下的可印区）排版，装不进纸面时**缩的只有图面**：页眉那一条、列头统计条、底部图签栏这三格恒为满幅，只有它们中间那块图吃缩放——这一步叫**配平**，摘要里写「**图面配平 82%**」。

- **跨页续排**以「一张卡」为最小单位开刀，切出来的每一段都是**完整的一张纸**：自己的页眉、自己的图签、自己的配平，不是把内容整块流到第二页。按周连排那张是四条竖列，一列一列各自吃到装不下为止；按人成册那张是报纸分栏，只能整段试排、二分找边界。续页上第一张卡贴回列头下沿，而列头那串「n 项 / 完成 x · y%」**仍按整周算**——只剩半截卡不能把一个人在这一周的工作量改小，两张纸上的「8 项」得是同一件事。被搬空的那一列不写「待补充」，改印**「本张无余项 / NOTHING FURTHER」**：那人的项在前一张纸上，叫读图的人去补是假话（只换文案不换盒子，纸面高度未动，切分时量的账不作废）。切开之后每张纸通常回到 100% 附近，而不是继续挤在 66% 上。
- **「上限 16 张」是真的会兑现**：周数那道上限（`clampCount`）只看**逻辑页**（一周一张、按人四张），而**续排发生在它之后**——一张纸被切成两半，物理纸张就往上涨。所以切完纸还有一次复核：按**实际纸张**对上限，超了就从**最旧的那一周**起丢一整周、整册重排（不能从尾巴上摘两张纸：张次、目录里的区间、图签的分母全都建立在完整的一册上，摘纸会让「第 09 / 17 张」当场对不上）。连排是从截止周往回数的，所以丢最旧的这个方向不用商量；你填的周数也不会被吞掉，重开对话框下拉还是原值，摘要会说「从最旧的周起丢掉 n 周（其中续排顶出 m 周），实排 k 周」。真丢到只剩一周还超（一个人一周灌了几十项），**照原样出纸**，摘要写「已超上限 n 张（只剩一周，没有可丢的周）」——宁可把超限说出来，也不悄悄少印一张别人的活。日常板子走不到这条分支（最满的一周 11 项，25 项才撞配平下限），它是给「批量出图 + 高密度」那种情况兜的底。摘要那几行也只说**这一册自己的数**：打开对话框时上一册量到的配平读数当场清零（那是唯一量不了的），丢周与超限那两句则由共用的那次排纸**按这一册重算**，不会跟着旋钮一起骗人。那一行开头的「N 张」**数的也是纸**：对话框摘要与真铺纸共用同一个 `planPapers()`，所以「说 6 张就铺 6 张」不是巧合而是同一次计算的两个出口 —— 有纸被切开时它照旧报纸张数（四周连排那册报 6 张，逻辑页只有 5），不再少报。唯一仍然量不到的是**配平**：那要真 DOM 才能量，所以对话框里就是不写配平，只有铺完纸的那条预览条会写。
- 一张图被拆到几张纸上时，四处同时改口：图签「张次」写 `SHT 03/10 · 本图 1/2`（`SHT` 是**装订位置**，`本图 n/m` 是**这张图自己的页数**；第一页不标「续」，从第二页起页眉图名才带「· 续」）；页眉写「第 03 / 10 张」；目录表那一行的张次写成区间 `03–04`；摘要写「续排 1 张 → 2 张」。
- **按人成册时，页眉那句还会带上自己那一卷的张次**：`第 07 / 09 张 · 本卷 02 / 02`。前半句是装订位置（这张在整册第几张），后半句是卷内位置（这一卷摊开是两张，这是第二张）——一叠纸摊在桌上分给四个人的时候，「杨威那一卷是不是少了一张」才是实际会问的问题，而装订位置回答不了它。卷表由 `_paginate()` 末尾按人聚合出来（`plan.volumes`，一个人在册里是连着排的，所以一卷就是纸张表上一段连续区间），图签栏那三格**一格不动**：`SHT` 是装订位置、`本图 n/m` 是一张图自己的页次、`VOL nn · 人名` 是卷身份，三个读数各有各的比较对象。**一册里只有一卷时不印这一格**（那一叠纸摊开就是自己那一卷，多给一格数字是给自己添乱），目录页脚那句解释跟着同一道闸。
- **目录页上每卷还有一条自己的小计**：`VOL 02 · 杨威 本卷 2 张 · 第 04–05 张 · 任务 6 项 · 欠 1 项`，排在**这一卷第一条数据行之前**。装订前你手里只有一张目录页，「这一卷该有几张、摊在第几张到第几张、几项活、还欠几项」这四个数此前都得靠把纸摊开或者逐行加；现在它们一行给全，而且四个数**各有各的对家**：张数与起止张次就是页眉用的那张卷表（所以页眉与小计不可能各说各话），任务数与欠项就是它下面那几行「任务 / 完成」两列之和，四卷再加起来等于页脚那句合计与横表右下角那格。它与页眉「本卷 k / m」**同一道闸**：一册只有一卷时两处都不印。它同时**替掉**了原来「换卷画一道加重横线」那道记号——一个「这里换卷了」画两遍，只会让人怀疑那是两件事。版面代价量过：一条小计行 21px、一册四条把索引表抬 +81px，目录页 `--nat` 仍 1047px、`--fc` 仍 1.0000，最满那一册（3 周 × 4 人 + 4 条小计 = 16 行）说明文字底下还剩 72px，那一格余量是断言守着的（目录页是整本册子里唯一没有续排保险的版面）。
- **「出纸会续页」这句是真数过页数的**：六种排法各跑一份 PDF——八周连排 9 页、按人成册两周 9 页、十五周顶上限 9 页、占位页 1 页、单周 33 项那例 **2 页**、一个人 30 项那例 **5 页**，全部 420×297mm、无空白页、无一张还带 `is-spill`。铁锈色虚线框（`.is-spill`）留作最后那道保险：只有单张卡自己就超过**那一页型的预算**（数据页 1153.57px，第十二轮起；判据装置自己造一张这样的纸来证明它还能亮，见 PROGRESS 决策 22 与决策 25 的例 I）时才会出现，那时摘要照旧写「N 张压到下限仍超纸面 · 出纸会续页」。
- **字体后落地要重排，不是重压**：思源宋体走 CDN，字一换行高就变，铺完纸之后再量可能高出几十像素。预览层在 `document.fonts.ready` 里重量一次，真超了就照新的行高重排一次册；绕过预览直接按 `⌘P` 那条路也一样，`beforeprint` 里 `fit()` 报超就重排。只重新配平是不够的——66% 的下限会把多出来的高度硬压回纸面，纸是装下了，字却凭空小一圈，而续排明明可以再给它一张纸。
- **这套纸在两个排版引擎上都对过账**：除了无头 Chromium（`page.pdf`），2026-09-22 又拿**系统 WebKit**（Safari 同一套引擎）一张纸一次地出了一遍。五例的「DOM 张数 / WebKit 页数 / Chromium 页数」三账现在是 `9/9/9`、`9/9/9`、`1/1/1`、`2/2/2`、`5/5/5`——**被切开的那两例两边都各自多出一张**，逐页身份（ASCII 图号 + 张次）与图签栏逐页判过，0 空白页、0 出界、0 盒内溢出，`:has()` 在 WebKit 下同样是绿的。逐张自然高 WebKit−Chromium 在没被切开的纸上正好是 0，在被切开的那张上是 −4 / −2px（两家换行点不同，都还在预算内）。**（这一格 2026-09-23 午后换了口径，原话留着**：图框不吃缩放之后，五个例子的纸盒全部恒为 `1512×1047pt = 400.0×277.0mm`，那一列减法两侧从此是同一个量、26 张纸全读 `+0`——「被切开的那张 −4 / −2px」是旧模型（连纸盒一起缩）才读得出的东西，从今天起它是一条接近恒等的检查，抓不到东西不等于没问题。代价一并写清楚：**跨引擎「这张纸自然高多少」这一格目前没有仪器**，要恢复得先给 WebKit 那条通道加一套中和手段，见 PROGRESS「还欠着的」第 1 条 ③。）**唯一还没证的仍是 Safari 打印面板自己的分页**：验证那台机器一台打印机都没配，无头打印链路走不通，得真按一次 `⌘P` → 「存储为 PDF」才算数。跑法与结论见 [PROGRESS.md](./PROGRESS.md)「关键决策」第 11 条。
- **目录页下面另起一张表：`任务分布 · Task Matrix`（人 × 周）**。上面那张按「张」列，读图的人要问的却是「这周压在谁身上、还欠几项」——那是另一个轴，所以另起一张表而不是给旧表加一列（加列只能算全周，算不了交叉）。四行制图人 × N 周 + 一列合计 + 一行全组合计，**格内写「未完成 / 任务数」**：「未完成」= 状态不是 `已完成`，板上三个状态（`未开始 / 进行中 / 已完成`）里前两个一律算欠着——这张表回答「还欠几项」，不回答「动到哪一步了」，后者是分图与修订表的活。格底一枚 2px 细条表示负荷，按**全表最满的一格**归一（不按行、不按周，横竖比都是同一把尺子），合计那一列与那一行不画（它是另一种量），并封顶 132px（否则两周那一册的条会胖成两块墨板）。右下角那格与目录页脚那句「合计 n 项、已完成 x 项」是同一笔账，`verify_sheet.py` 逐格把它跟 `tasksFor` 现算的数对一遍。**只画在目录的第一张纸上**，续页不重复。它吃进去的是目录页中间本来就有的那片白：`--nat` 恒 1047px、`--fc` 恒 1.0000，六种排法的张数与配平一格未动。
- 一张都排不出来时（比如按人成册、而这个区间四个人都没排任务，或者筛选把内容滤空了）**不是出一片空白**：出一张**「此页无图 · No Work To Plot」占位页**，张次写 `NIL`，页面上写清楚是**区间没数据**还是**收录范围把它滤空了**，以及换哪个旋钮能看到东西。
- 「预览」在屏幕上叠出整册纸，顶栏可「改设置」重开对话框、「晒图」出纸、「回到看板」退出；「晒图」直接调浏览器打印。
- 每张纸底部都有**图签栏**：部门 / 图名 / 周期 / 图号 / 册 / 张次 / 签发 / 比例 `NTS` / 版次 `R1` / 制图。单周图号 `WTP-YYYY-Www`，整套图用区间号 `WTP-2026-W37–39`；张次在目录页写 `INDEX`，其余写 `SHT 03/13`——**分母是物理纸张数**，目录页和被切开的续页都各自占一张、都进分母，被拆开的图再带一格 `· 本图 n/m`。「周期」一格只写这张纸自己那一周，整册头尾写在目录页的说明里。图签栏**钉在纸的下边线**（图面块 `flex: 1 1 auto` 自己吃掉剩余高度）：活少时空白留在图框里读作「这周就这么点活」，留在纸尾读作「没人排版」。
- 每条人列的列头左上角那枚编号：看板上是**图幅号** `SHT 01`…`SHT 04`（9px 等宽灰字压在人名上方），出图时换成 `分图 01…04`——一张 A3 上它们是四张子图。列左上与右下各一枚**裁切标记**（`.column::before/after`，50% 透明度的直角）照旧出现。
- 打印时自动切回**纸面配色**（蓝图夜览不进打印机：`#print-stack` 上单独覆写一层纸面令牌），并强制 `print-color-adjust: exact`，因为剖面线与尺寸线的填充是这张图的信息。纸面文字逐类量过对比度：三种版面 52 / 50 / 10 类文字，**全部达标**（比上一版多的那一类两册都是 `第 N 周` 那一族，整族 `visibility:hidden` 再量一遍就各回到 51 / 49），最紧的是「中」优先级徽标与 `新增` 标签的 **5.42:1**（8.5–9.5px 小字压白底，门槛 4.5），铁锈红那一族最紧的是 **5.65:1**（横表那枚 11px 欠项数、目录卷小计里那句 10.5px「欠 n 项」、`第 N 周` 那 18 / 10 枚同值——反白那一档比的是同一对颜色反过来，比值一样）——晒出去贴在墙上仍读得清。**反白那一档另外量过一次「不打折」**：真数据那册（按周连排八周 + 目录）九张纸 `--fc` 全 1.0000，那枚 8.5px 的徽标落纸 **2.249mm = 6.38pt**、比值 5.65:1，纸面证据在 `docs/screenshots/2026-09-23-sheet-longbadge-real.png`（此前这一档只有 fixture 那三张撑，见 PROGRESS「还欠着的」）。
- 绕过对话框直接按 `⌘P` 也不会打出白纸：`beforeprint` 先按当前设置铺一次纸，已有纸面就重新配平一次。

### 保存、同步与备份

- 改任何字段都会**去抖上传**（`pushDebounced`），右下角悬浮保存条实时显示四种状态：`✓ 已同步` / `↑ 点击上传到云端` / `◎ 上传中…` / `! 或 ↻ 失败`。
- 关页面前若还有未上传的改动，用 `pagehide` + `fetch(keepalive)` 补发一次。
- **上传一律先拉后推**：本次会话没真读到过云端时（`GistSync.reachable === false`），拒绝直接上传，先补一次 pull→merge。这条是硬不变量，原因见 [PROGRESS.md](./PROGRESS.md)。
- 失败提示区分三类：`Token 失效`（去设置里换）、`连不上云端`（点击重试）、`读不到云端`（检查 Gist ID）。
- ⚙ 设置里可改 Gist ID / Token，另有**导出 JSON / 导入 JSON / 断开关**。导出的文件名带周与日期，导入前会校验 `schemaVersion` 属于 `READABLE_VERSIONS`（当前 `[1,2,3]`），并按同一套 merge 语义合进来。

## 怎么用

新成员第一次进来**就能看到四个人的板子**（读云端不需要凭据，本轮实测过），但要让他自己的改动能上云，得配一次同步（**每人每台浏览器各配一次**）：

1. 点 ⚙ 设置；
2. Gist ID 填 `1c847a7d6d0e61fb090eb581d5e988b7`（源码里已有默认值，一般不用改）；
3. Token 粘一个 **fine-grained PAT**：`Account permissions → Gists → Read and write`，有效期可选 No expiration。注意仓库级授权不包含 Gist，必须走 Account 那一栏；
4. 点「保存并同步」。程序会先拉云端、和本地合并、再上传合并后的那份——所以本地哪怕是一张空板子也不会把云端抹掉。

Token 只存在这台浏览器的 `localStorage.renderTrackerSyncConfig` 里。

> **给后续维护者的硬规矩**：新 token 绝对不要写进 `index.html`、任何仓库文件或笔记里。历史上写进过源码的 `ghp_…` 被 GitHub 的 secret scanning 自动吊销过，全组同步静默停摆约两个月。仓库里那个 `DEFAULT_TOKEN` 是**已经失效的旧值**，保留只为兼容旧行为，不要拿它发任何请求。

## 设计语言与术语

这块板子刻意做成一张**建筑制图图纸**，界面上的每个视觉元素都对应制图习惯，而不是随便的装饰：

| 界面元素 | 制图来源 |
| --- | --- |
| 满屏细格 18px + 粗格 144px | 制图网格 / 坐标纸 |
| 卡片进度的横条与端点 | **尺寸线**（dim line） |
| 优先级代号 `P1/P2/P3` + 下画线 | 图纸**标注**（代号在下、实值在后） |
| 「已完成」的卡片整张打 45° 斜纹 | **剖面线**（hatch）——图纸上被剖切到的面 |
| 新增卡片内侧虚线 | **修订云线**的轻量版 |
| `REV n` 徽标与修订表 | 图纸**修订表**（revision schedule） |
| `第 N 周` 徽标（`≥ 4` 整枚反白） | 施工进度**横道图**上那根跨了几周的条——一眼读出「这项压在他身上多久了」；反白是横道图里过节点那几根的画法（第 4 周意味着跨了一整个月） |
| 每张纸底部的部门 / 图号 / 比例 / 版次 | **图签栏**（title block）——一套图里每张都有，不是只有末页 |
| 图册首页的张次表 | **图纸目录**（drawing index），张次写 `INDEX` |
| 目录页下面那张人 × 周的格子表 | **任务分布横表**（表头写 `任务分布 · Task Matrix`）——目录按张列、这张按「人 × 周」列，另一个轴就另起一张表，不给旧表加列 |
| 按人出图时的 `VOL 01…04` | **分册**：一人一卷，卷内按周从旧到新。页眉那句「本卷 k / m」数的就是**这一卷自己摊开的张数**，与「第 NN / MM 张」那个全册张次各说各的 |
| 目录页里每卷开头那一行 `VOL 02 · 杨威 本卷 2 张 · 第 04–05 张 · 任务 6 项 · 欠 1 项` | **卷小计**（装订前的核对行）——摊开之前就能知道这一卷该有几张、从第几张到第几张、几项活、还欠几项。它替掉了原来「换卷画一道加重横线」那个记号 |
| 人列列头的 `SHT 01`…`04` / 出图时的 `分图 01…04` | 图幅编号 sheet number（看板上四条列＝四张图幅；一张 A3 上它们是四张子图） |
| 人列左上 / 右下两角的直角 | **裁切标记**（crop marks） |
| 一张 A3 装不下时多出来的那张纸 | **续图**：一张图占几张纸，`· 本图 n/m` 与图名上那枚「· 续」都是它 |
| 续页上那一格空列 | **「本张无余项 / NOTHING FURTHER」**：他的项在前一张纸上，不是「待补充」 |
| 单张卡自己就超过预算时那圈虚线 | **续图提示**：宁可让它出界，也不把字压到读不得（最后那道保险，日常走不到） |
| 「打印」叫「**晒图**」 | 蓝图晒制工艺 |
| 「**配平**」= 把版面等比压进 A3 纸面 | 自造术语（借用「配页」的语感），代码里就是 `SheetSet.fit()` |

术语在 UI 与代码注释里保持一致：晒图、图签、云线、尺寸线、修订、配平、册 / 分图 / 张次、任务分布、卷小计、周 `W39`、图号 `WTP-`。

字体：**Noto Serif SC**（标题/中文，衬线，图纸标题气质）+ **IBM Plex Mono**（数字与标签，等宽，读数值像标注），带 `font-display: swap` 和离线回退栈——断网时退到系统字体但版面不塌。数字统一 `font-variant-numeric: tabular-nums`。

几处值得先读注释再动的实现：

- `GistSync.merge`：id 取并集、`updatedAt` 新的赢、墓碑与任务比时间。**唯一**的合并实现，备份导入也走它。
- `GistSync._doPush` 开头的 `reachable` 闸门。
- 卡片模板里日期中间那枚 `—`（`<em aria-hidden="true">`）是尺寸线连接符，不是文本。
- CSS 里的「点击热区」小节：小控件用透明 `::after` 向外借空白，**不要**为此放大字号。
- 出图的缩放**只能走 `transform`**：`.sheet-page` 固定 1512×1047 排版，`.sheet-paper` 的占位高度由 JS 量出自然高后写回 `--nat`（`transform` 不改盒子占位，不写回去纸会叠纸）。`@media print` 里 `--fit: var(--fc,1)` 把屏上适配那一层 `--fv` 摘掉——**屏上缩小不影响出纸尺寸**。
- 纸上那几个「只影响观感」的选择器别当冗余删：`.sheet-page > .sheet-board, .sheet-nil, … { flex: 1 1 auto }` 是让图签栏贴住纸的下边线（留白归图框，不归纸尾）；`.task-name:has(> .placeholder)::after` 只给**真的挂着占位文案**的那张卡补 `（未命名）`——写成 `.task-name::after` 会给有名字的卡也补一刀。`:has()` 需要 Safari 15.4+ / Chrome 105+，万一不兼容只会少了 `（未命名）` 那三个字，不会漏掉隐藏提示。
- **切几刀全靠那枚探针** `#sheet-probe`：它带的是同一个 `.sheet-paper`、同一套 CSS，铺在屏外量「这一段卡放进这张纸到底有多高」（报纸分栏那种流式版面没法在 JS 里模拟，只能整段试排）。量完 `_dropProbe()` 立刻摘掉，所以打印时它并不存在——`@media print{#sheet-probe{display:none}}` 只是道保险。**别把它当调试残留删**，也不要给那条 `display:none` 加 `!important` 之外的新装置：任何让它「在屏上也不存在」的改动都会让 `_paginate` 以为什么都装得下，续排整条路静默失效（harness 就真栽过一次，见 PROGRESS「测量陷阱」）。

## 数据格式与同步语义

```jsonc
{
  "schemaVersion": 3,
  "currentWeek": "2026-W39",
  "tasks": [{
    "id": "…", "person": "…", "week": "2026-W39", "name": "…",
    "priority": "中", "status": "进行中", "progress": 83,
    "startDate": "2026-09-14", "dueDate": "2026-09-20", "notes": "…",
    "order": 3, "createdAt": "…", "updatedAt": "…",
    "history": [{ "at": "…", "field": "progress", "from": "60", "to": "83" }]
  }],
  "tombstones": { "<被删除任务 id>": "<删除时刻 ISO>" }
}
```

- **v1 → v2**：加了 `history` 与字段规范化。
- **v2 → v3**：加了 `tombstones`。**没有墓碑的话删除无法同步**——某个人的删除传上云后，另一个人的旧本地状态里没有那条删除记录，一合并就把删掉的任务「还魂」。
- 合并时墓碑**不会被清空**：任务已经不在了就继续留着往外传；只有当任务的 `updatedAt` 晚于删除时刻（说明有人把它改回来了 / 撤销了删除）才作废该墓碑。
- 云端 Gist 是**唯一真数据**；本地 localStorage 只是缓存。
